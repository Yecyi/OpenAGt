Make multiple edits to a single file in one operation. Built on top of the Edit tool. Prefer this over Edit when you have several changes to make to the same file.

# Before using

1. Use Read to understand the file's contents and context.
2. Verify the directory path is correct.

# Inputs

1. `file_path`: absolute path to the file (must be absolute, not relative).
2. `edits`: an array of edit operations, each containing:
   - `oldString`: the text to replace (must match the file contents exactly, including whitespace and indentation).
   - `newString`: the replacement text.
   - `replaceAll`: replace all occurrences of `oldString`. Optional, defaults to false.

# Behavior

- Edits apply in sequence, in the order provided. Each edit operates on the result of the previous edit.
- Either all edits succeed and apply atomically, or none apply.
- Plan edits to avoid conflicts: an earlier edit must not destroy text that a later edit is trying to find.

# Failure modes

- `oldString` does not match the file contents exactly (including whitespace).
- `oldString` and `newString` are identical.
- An earlier edit changed text that a later edit relied on.

# When making edits

- Result must be idiomatic, correct code. Do not leave the file in a broken state.
- Always use absolute paths (starting with `/`).
- No emojis unless the user explicitly requests them.
- Use `replaceAll` for renames across the file (e.g., variable renames).

# Creating a new file

- Pass a new file path (including any directory parts).
- First edit: empty `oldString`, full file contents as `newString`.
- Subsequent edits: normal edit operations on the just-created content.
