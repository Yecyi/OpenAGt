Escalate to the user's inbox when you need a decision or input that you cannot derive from the tools available to you.

Use this tool when:
- A precondition is missing that requires user judgment, not just information.
- A risk threshold is reached: about to delete data, push to a remote, commit secrets, or run a destructive shell command without clear authorization.
- The estimated effort exceeds the budget the user appears to have expected for this task.

The user sees the inbox item via the inbox CLI command or the web client. Behavior depends on the `blocking` flag:
- blocking: false (default) — record the issue and continue with a safe fallback if one exists.
- blocking: true — pause work that depends on this resolution. The user will reply via the inbox.

Parameters:
- question: the question or blocker, plain language.
- context: 1–3 sentences of relevant state — what you were trying to do and why this blocks.
- priority: "high" / "normal" / "low" — how soon this should surface in the user's inbox.
- blocking: whether to mark the inbox item state as "blocked" so it stands out.
- resume_with: optional goal string the user can attach when resolving the item.

Returns the inbox item ID. Choosing to escalate is a valid outcome, not a failure — prefer it over guessing past a real blocker.
