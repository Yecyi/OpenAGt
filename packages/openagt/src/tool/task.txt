Launch a new agent to handle complex, multistep tasks autonomously.

Specify a `subagent_type` parameter to select which agent to use.

# When to use

- When you are instructed to execute a custom slash command. Pass the slash command invocation as the entire prompt.
  Example: `Task(description="Check the file", prompt="/check-file path/to/file.py")`

# When NOT to use

- Reading a specific file path → use Read or Glob, not Task.
- Searching for a specific class definition (e.g., `class Foo`) → use Glob, not Task.
- Searching within a specific file or 2-3 known files → use Read, not Task.
- Anything outside the agent descriptions registered in this session.

# Usage notes

1. **Parallelism.** Launch multiple agents concurrently when their work is independent. Send a single message with multiple Task tool calls.

   1a. **Broad codebase analysis (deep dive, architecture, technical details, algorithms, key technology outline):** do not launch one generic Explore agent over the whole repository. Launch 3-4 Explore agents in parallel with non-overlapping scopes, then synthesize the results yourself or via a reducer/general agent. Default shards: structure/entrypoints, agent runtime/tools/coordinator, data/memory/safety/events, tests/release/docs.

2. **Result handling.** When the agent finishes, it returns a single message. The result is NOT shown directly to the user — relay a concise summary in your reply. The result includes a `task_id` you can reuse later to continue the same subagent session.

3. **Fresh vs. resumed context.** Each Task invocation starts with a fresh context unless you provide `task_id` (which resumes the same subagent session with its previous messages and tool outputs). On a fresh start, the prompt must be highly detailed — describe the task autonomously and specify exactly what information the agent should return in its final message.

4. **Trust.** The agent's outputs should generally be trusted. Verify with a read or test if the work is high-stakes.

5. **Mode and verification.** Tell the agent whether you expect it to write code or only research (search, file reads, web fetches). It does not see the user's intent. Tell it how to verify its work when relevant (e.g., the right test command).

6. **Proactive use.** If an agent's description says it should be used proactively, try to use it without the user having to ask first.
