## Highlights

OpenAGt v1.21.1 is a patch release that closes the four April-2026 runtime
debts that survived the v1.21.0 cut, adds a structural defense around the
tool-registry TDZ trap, ships a missing migration that v1.21.0 needed but
forgot, and synchronises README + version-script metadata with the actual
release line.

This is a maintenance release — no new feature surface, no schema changes
beyond the missing `personal_memory_note.kind` column the runtime already
expected. Existing v1.21.0 configurations need no changes; the deprecation
warnings introduced here are warn-only with hard-removal planned for v1.23.

## Bug fixes

- **Memory writes no longer crash on a fresh database.** v1.21.0 added a
  `kind` column to `personal_memory_note` in `personal/personal.sql.ts:14`
  but did not commit a migration. Every fresh install hit
  `SQLiteError: table personal_memory_note has no column named kind` on the
  first memory write at `personal/personal.ts:119`. v1.21.1 adds migration
  `20260503000000_personal_memory_kind` with the column (`text NOT NULL
  DEFAULT 'belief'`) and the matching `personal_memory_kind_idx` index.
  Closes `inc.kind-migration` in the issue tracker.
- **MCP tools-changed events are now persisted to the event ring buffer.**
  The bus persistence whitelist had `"tools.changed"` but the actual
  emitted event type is `"mcp.tools.changed"` — every MCP tools-changed
  event since the buffer was added was silently dropped. Fixed by aligning
  the whitelist to the emitted name and pinning the contract via
  `test/bus/critical-events.test.ts`. Closes April finding 4.3.
- **Provider fallback respects configured backoff under a 429 storm.**
  `provider/fallback-service.ts` defined `computeBackoff()` but never
  invoked it; the chain rotated at full speed. Backoff now sleeps
  `computeBackoff(state.attempts, policy)` between hops when
  `state.attempts > 0` (the first hop after a failure runs immediately
  because the user already paid the failed-call latency). Closes April
  finding 4.5.
- **Multi-instance environment-prompt cache no longer cross-contaminates.**
  `session/system.ts` `environmentMemo` used a fixed `"environment"` key
  with date-only hashing. A process serving two models or two workspace
  contexts could return one model's static prompt block to the other.
  Cache key is now partitioned by
  `${providerID}:${api.id}:${directory}:${worktree}:${vcs}:${platform}`.
  Closes April finding 4.1.

## Performance

- **Coordinator dispatch sweep is no longer O(K·N) storage reads.**
  `task-runtime.ts canRun()` previously called `list()` per invocation, so
  a sweep of K ready tasks paid O(K·N) reads where N is the total task
  count in the session. The dispatch loop now passes its pre-fetched
  `allTasks` snapshot via the new optional `tasks?: TaskRecord[]`
  parameter on `canRun`, dropping a sweep to O(N) reads + O(K) snapshot
  evaluations. Single-task callers (the `task` tool, fixtures) retain the
  no-snapshot fast path. Closes April finding 4.7.

## Structural defenses

- **Tool-registry import audit (`bun run check:tool-imports`).** Wave 11 A1
  worked around the canonical TDZ trap by extracting `PersonalAgent.Service`
  into `personal/service.ts` so tool implementations can hold the Service
  tag without dragging coordinator → agent.defaultLayer into the registry
  load chain. The new `script/audit-tool-imports.ts` rejects any future
  tool implementation that imports `personal/personal` (block),
  `coordinator/coordinator` (block), or `agent/agent` (warn). Type-only
  imports are skipped — they're erased at compile time and never trigger
  module load. Framework files (`tool/registry.ts`, `tool/tool.ts`,
  `tool/truncate.ts`) are exempted. The fixture at
  `script/fixtures/tool-bad-import.ts` and the test at
  `packages/openagt/test/script/audit-tool-imports.test.ts` keep the rule
  from silently bit-rotting. AGENTS.md gains a sibling subsection ("Tool
  registry imports") to the existing prompt-affect documentation.
- **Single-source finding tracker (`docs/audit/issue-tracker.md`).** Five
  standalone analysis docs already lived under `docs/`, each rediscovering
  the same April debts because there was no shared index. The 2026-05-02
  session would have been the sixth. The tracker indexes every actionable
  finding from a doc or session transcript with `source | finding |
  file:line | status | closing commit`. New analyses **append rows** here
  instead of creating another standalone analysis doc. Closing rows are
  kept (not deleted) so a later reviewer can see what was addressed and
  when.

## Documentation & metadata

- **README release section updated to v1.20.2 + v1.21.0.** Previous text
  pointed at v1.16.0 stable + v1.17.0-rc.3 RC; both stale. The README now
  links to the v1.21.0 release notes, calls out v1.20.2 as the previous
  stable, and explicitly notes that the v1.17 RC line was never promoted —
  so anyone reading the README knows why the project jumped 1.16 → 1.20.
- **`bun run verify:v1.21` ships.** The misleading `verify:v1.17` script
  (which actually invoked `script/v1.16-verify.ts`) is removed.
  `script/v1.21-verify.ts` mirrors the v1.20 verifier shape and adds two
  v1.21-specific gates: a presence check for the four v1.21 migration
  directories (`calibration_records`, `schema_version_table`,
  `advisory_locks`, `prompt_outcomes`), and a focused run of the `db
  status` integrity smoke test (closes hazards H5/H8/H9/H13 from the
  v1.21.0 hazard register).
- **`AGENTS.md` default branch corrected to `main`.** The historical `dev`
  line is no longer the integration branch; recent waves land directly on
  `main`. AGENTS.md previously said "default branch is `dev`", which sent
  any contributor following it for a diff base to the wrong place.

## Compatibility

- **`.opencode/` discovery accepts both singular and plural forms, with a
  warn-only deprecation.** Seven config families used dual-form globs
  (`agent/agents`, `command/commands`, `mode/modes`, `expert/experts`,
  `plugin/plugins`, `tool/tools`, `skill/skills`). A user splitting files
  between forms saw neither realize the other existed. v1.21.1 keeps both
  forms discovered (no behaviour change for existing setups), but logs a
  one-time deprecation warning per `(canonical, deprecated)` pair when a
  discovered file lives under the deprecated form. Canonical map matches
  what `.opencode/` ships on disk in this repo: agent / command / mode /
  expert / tool stay singular; skills / plugins stay plural. **Hard
  removal of the deprecated form is planned for v1.23**, giving two minor
  versions of warning lead time.

## Verification

```bash
cd packages/openagt
bun typecheck
bun test test/agent test/personal test/bus test/session test/provider test/config test/script
bun run check:prompt-affect -- --fail-on-block       # 0/0 (unchanged baseline)
bun run check:tool-imports -- --fail-on-block        # 0 block / 1 warn
cd ../..
bun run verify:v1.21
git diff --check
```

The `check:tool-imports` 1-warn finding is the existing
`tool/task.ts` namespace import of `agent/agent`; flagged for review,
not blocking.

Pre-existing test drift surfaced (but not introduced) by Phase A
verification:

- `test/agent/mpacr-partial-failure.test.ts` — `synthesis enforces quorum
  before accepting model output` times out at 5s on `main` and on this
  branch. Tracked separately from this release.
- `test/agent/prompt-templates-snapshot.test.ts` — six byte-equal
  template assertions diff against the current `coordinator/prompts/*`
  templates on both `main` and this branch. The templates evolved; the
  byte-equal snapshots have not been refreshed.
- `test/session/processor-effect.test.ts` — two `mark pending tools as
  aborted on cleanup` cases hit `instance: No context found for instance`
  via `bus/index.ts:399 publish` during cleanup. Confirmed pre-existing
  on `main`. Tracked as `inc.processor-effect-failures` in the issue
  tracker.
